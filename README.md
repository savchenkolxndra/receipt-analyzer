# Чек → Аналітика

Вебсервіс для аналізу витрат за фотографіями чеків. Користувач фотографує чек, хмарна модель **Google Gemini** розпізнає магазин, дату, товари й суми та розносить товари за категоріями. Дані зберігаються в хмарній базі **Supabase (PostgreSQL)**, а на дашборді видно витрати за категоріями, за днями і топ магазинів.

Проєкт – прототип інтеграції хмарних сервісів:

| Модель | Сервіс | Роль у проєкті |
|---|---|---|
| AIaaS | Google Gemini API | розпізнавання фото чека → структурований JSON |
| DBaaS | Supabase (PostgreSQL) | зберігання чеків і товарів |
| PaaS | Render | запуск вебсервера, публічне посилання |

## Як це працює

```
Телефон/браузер ──фото──▶ FastAPI-сервер (Render) ──фото + промпт + JSON-схема──▶ Gemini API
                                 │                ◀──────── JSON чека ─────────────┘
                                 ▼
                      користувач перевіряє дані
                                 ▼
                       Supabase (PostgreSQL) ──SQL GROUP BY──▶ дашборд (Chart.js)
```

1. **Розпізнавання.** Фото надсилається в Gemini разом з інструкцією та схемою `ParsedReceipt` (`response_schema`). Модель одним запитом читає текст (OCR), розбирає його на позиції й визначає категорію кожного товару, а повертає строго валідний JSON.
2. **Перевірка.** Користувач бачить розпізнані дані, може виправити будь-яке поле, додати чи видалити рядок. Сервіс звіряє суму позицій із підсумком чека.
3. **Збереження та аналітика.** Чек зберігається в базу, а статистика рахується SQL-запитами з групуванням за категоріями, днями й магазинами. Є фільтр за періодом.

Якщо основна модель перевантажена (помилки 429/503), запит автоматично йде до запасної моделі зі списку `GEMINI_MODELS`.

## Структура

```
app/
  main.py        – REST API та віддача веб-сторінки
  gemini.py      – виклик Gemini API, промпт, запасні моделі
  schemas.py     – схеми даних (Pydantic), зокрема схема відповіді Gemini
  db.py          – моделі таблиць (SQLAlchemy), SQLite або PostgreSQL
  config.py      – налаштування зі змінних середовища
  static/        – веб-інтерфейс (HTML + JS + Chart.js)
tests/test_api.py – тести (Gemini замінено заглушкою)
render.yaml      – конфігурація деплою на Render
```

## Запуск локально

1. Отримати безкоштовний ключ Gemini API: https://aistudio.google.com/apikey
2. Встановити залежності:
   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. Скопіювати `.env.example` у `.env` і вписати `GEMINI_API_KEY`. `DATABASE_URL` локально можна не задавати – створиться файл `receipts.db`.
4. Запустити:
   ```bash
   uvicorn app.main:app --reload
   ```
   - Веб-інтерфейс: http://127.0.0.1:8000
   - Документація API (Swagger): http://127.0.0.1:8000/docs

Тести (ключ і інтернет не потрібні):
```bash
pytest
```

## REST API

| Метод | Шлях | Опис |
|---|---|---|
| POST | `/api/receipts/parse` | фото (multipart, поле `file`) → розпізнаний чек, модель, час |
| POST | `/api/receipts` | зберегти чек (JSON) |
| GET | `/api/receipts` | список чеків з товарами |
| DELETE | `/api/receipts/{id}` | видалити чек |
| GET | `/api/stats?date_from=&date_to=` | аналітика за період |

## Деплой у хмару

**База – Supabase**
1. Створити проєкт на https://supabase.com (безкоштовний план).
2. *Connect → Connection string*, режим **Session pooler**, скопіювати рядок і підставити пароль бази. Це і є `DATABASE_URL`. Таблиці створяться автоматично під час першого запуску.

**Сервер – Render**
1. Залити проєкт на GitHub.
2. На https://render.com: *New → Blueprint*, вибрати репозиторій (Render прочитає `render.yaml`).
3. Вписати змінні `GEMINI_API_KEY` і `DATABASE_URL`.
4. Після збірки сервіс буде доступний за посиланням `https://receipt-analyzer-xxxx.onrender.com`.

> На безкоштовному плані Render сервер «засинає» після простою, тому перше відкриття може тривати до хвилини.

## Обмеження прототипу

- Без акаунтів: усі чеки спільні для всіх, хто відкриє сайт.
- Розпізнавання не ідеальне: м'яті, вицвілі чи обрізані чеки можуть читатися з помилками, тому дані потрібно перевіряти перед збереженням.
- Знижки на весь чек і бонуси не розносяться по товарах, через що сума позицій може відрізнятися від підсумку.
- Категорії фіксовані (12 штук).
- На безкоштовному рівні Gemini діють ліміти запитів, а надіслані дані Google може використовувати для покращення своїх продуктів.

## Можливий розвиток

- Firebase Authentication / Supabase Auth – особисті акаунти.
- Supabase Storage – зберігання фото чеків.
- Місячні звіти й поради щодо економії (другий запит до Gemini).
- Експорт у CSV/Excel, бюджети за категоріями.
